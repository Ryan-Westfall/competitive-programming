# Competitive Programming Database

**Public archive of my competitive programming solutions** – currently LeetCode, with support planned for Codeforces, Topcoder, etc.

Primary consumer: [https://ryan-westfall.info/archive](https://ryan-westfall.info/archive) – my portfolio website queries this repo's JSON data to display a filterable archive of solved problems.

**Repo:** `https://github.com/Ryan-Westfall/competitive-programming`

## For AI / Automation – How to Use This Repo

If you are an AI agent directed at this repo, here is what you need to know:

### Purpose
This repo is a **database**, not a library. It stores:
- **Solutions** – one folder per solved problem
- **Metadata** – machine-readable JSON for each solution
- **Notes** – my personal notes per problem (markdown)
- **Aggregated data** – JSON files for website consumption

### Directory Structure
```
competitive-programming/
├── leetcode/
│   ├── 1-two-sum/
│   │   ├── README.md          # Problem description (from LeetCode, HTML)
│   │   ├── solution.py        # My accepted solution (most recent submission)
│   │   ├── metadata.json      # Machine-readable problem info
│   │   └── notes.md           # My notes (optional, created via website + extension)
│   ├── 2265-count-nodes-equal-to-average-of-subtree/
│   │   └── ...
│   └── ... (584 problems as of 2026-09)
├── data/
│   ├── problems.json          # Array of unique solved problems (no _ts)
│   ├── archive.json           # Same as problems.json but with _ts for sorting
│   ├── tags.json              # { allTags: [{tag, count}], leetcodeTags: [...] }
│   ├── stats.json             # { total: {uniqueSolved}, difficulties: {Easy,Medium,Hard}, ... }
│   └── notes.json             # { "<slug>": {title, frontendId, updatedAt, preview, path} }
├── scripts/
│   └── generate_archive.mjs   # Regenerates data/*.json from leetcode/*/metadata.json
└── README.md                  # This file
```

### Problem Folder Format: `leetcode/<frontendId>-<slug>/`

Each folder name is `<frontendId>-<slug>` where:
- `frontendId` is LeetCode's frontend ID (e.g., `1`, `2265`) – may be null for some problems
- `slug` is LeetCode's title slug (e.g., `two-sum`)

**Files inside each folder:**

#### 1. `metadata.json` – The source of truth for that problem
```json
{
  "questionId": "1",
  "frontendId": "1",
  "title": "Two Sum",
  "titleSlug": "two-sum",
  "difficulty": "Easy",
  "tags": ["array", "hash-table"],
  "tagNames": ["Array", "Hash Table"],
  "lang": "python3",
  "langVerbose": "Python 3",
  "runtime": "48 ms",
  "runtimePercentile": 92.3,
  "memory": "16.5 MB",
  "memoryPercentile": 88.1,
  "timestamp": 1789004139
}
```
- `tags`: array of slugs (kebab-case, e.g., `depth-first-search`)
- `tagNames`: same tags with proper casing (e.g., `Depth-First Search`)
- `timestamp`: Unix timestamp (seconds) of submission, used for sorting

#### 2. `solution.*` – My accepted solution
- Filename is `solution.py` (or `.js`, `.ts`, `.java`, `.cpp`, etc. – currently all Python)
- Contains the full accepted submission code as submitted to LeetCode
- **Most recent submission per problem** – if I solve same problem in multiple languages, latest overwrites

#### 3. `README.md` – Problem description
- Generated by `leetcode-github-sync` extension from LeetCode's HTML description
- Contains: title, slug, ID, difficulty, tags, companies, language, runtime, memory, submitted date, link, then `## Description` with HTML, then `## Hints`, `## Solution` (points to solution file)

#### 4. `notes.md` – My personal notes (optional)
- Created/edited via website at `ryan-westfall.info/archive` (requires LeetSync extension to save)
- Also can be created locally
- Format:
```markdown
# Notes: Two Sum

**Problem:** two-sum
**Frontend ID:** 1
**Updated:** 2026-09-10T19:51:35.872Z

---

Your notes here in markdown...

---
*Synced via LeetSync extension from ryan-westfall.info*
```
- The middle section between `---` delimiters is the actual notes content (parsed by website)

### Aggregated Data Files: `data/*.json`

These are **generated** by `scripts/generate_archive.mjs`, not hand-edited. They are what the website queries via raw GitHub URLs.

#### `data/problems.json` – Array of unique solved problems
```json
[
  {
    "platform": "leetcode",
    "id": "two-sum",
    "title": "Two Sum",
    "url": "https://leetcode.com/problems/two-sum/",
    "language": "python3",
    "solvedAt": "2026-09-10T01:35:39.000Z",
    "difficulty": "Easy",
    "frontendId": "1",
    "questionId": "1",
    "dir": "leetcode/1-two-sum",
    "tags": ["array", "hash-table"],
    "tagNames": ["Array", "Hash Table"]
  }
]
```
- `id`: slug
- `dir`: path to problem folder (e.g., `leetcode/1-two-sum`)
- Sorted by `solvedAt` descending (newest first) in `archive.json`, same in `problems.json`

#### `data/archive.json`
Same as `problems.json` but includes `_ts` field (Unix timestamp) for sorting:
```json
{
  "platform": "leetcode",
  "id": "two-sum",
  "title": "Two Sum",
  "_ts": 1789004139,
  ...
}
```

#### `data/tags.json`
```json
{
  "allTags": [
    {"tag": "array", "count": 306},
    {"tag": "string", "count": 121},
    ...
  ],
  "leetcodeTags": [...] // same as allTags currently
}
```
- Tags sorted by count descending
- Used for filter UI

#### `data/stats.json`
```json
{
  "total": {"uniqueSolved": 584},
  "difficulties": {"Easy": 168, "Medium": 329, "Hard": 87},
  "generatedAt": "2026-09-10T12:58:00Z"
}
```

#### `data/notes.json` – Index of notes
```json
{
  "two-sum": {
    "title": "Two Sum",
    "frontendId": "1",
    "updatedAt": "2026-09-10T19:51:35.872Z",
    "preview": "First 200 chars of notes...",
    "path": "leetcode/1-two-sum/notes.md"
  }
}
```
- Key is slug (`id`)
- `preview`: first 200 chars of notes content
- `path`: relative path to notes.md file

### How Data Flows

1. **LeetCode submission** → `leetcode-github-sync` Chrome extension detects accepted submission
2. Extension creates/updates `leetcode/<id>-<slug>/` with `solution.*`, `README.md`, `metadata.json` via GitHub API (using my token)
3. Extension or manual run: `node scripts/generate_archive.mjs` → regenerates `data/*.json`
4. Website at `ryan-westfall.info/archive` fetches via raw GitHub:
   - `https://raw.githubusercontent.com/Ryan-Westfall/competitive-programming/main/data/problems.json`
   - `.../tags.json`, `.../stats.json`
   - For problem detail: `.../<dir>/README.md` and `.../<dir>/notes.md` and `.../<dir>/solution.py`

### For AI – Adding a New Problem

If you are asked to add a solution:

1. Create folder `leetcode/<frontendId>-<slug>/` (e.g., `leetcode/42-trapping-rain-water/`)
2. Create `metadata.json` with required fields:
   - `questionId`, `frontendId`, `title`, `titleSlug`, `difficulty` (Easy/Medium/Hard), `tags` (array of slugs), `tagNames` (array of display names), `lang`, `timestamp`
3. Create `solution.py` (or appropriate extension) with solution code
4. Create `README.md` with LeetCode description (or minimal version)
5. Run `node scripts/generate_archive.mjs` to update `data/*.json`
6. Commit and push – website will pick up new raw JSON immediately

**Do NOT:**
- Hand-edit `data/*.json` – they are generated
- Delete existing folders without regenerating archive
- Use non-kebab-case for `tags` slugs (use `array`, not `Array`)

### For AI – Adding/Editing Notes

Notes are stored in two places:
- `leetcode/<id>-<slug>/notes.md` – full notes file
- `data/notes.json` – index for quick lookup

When editing notes via website:
- Website checks `localStorage` for `leetcode-notes-<slug>` for immediate read of own writes (due to GitHub delay)
- Saves via `LeetSync` extension which does GitHub API PUT with 409 retry logic and merge
- Notes format must preserve header/footer with `---` delimiters, middle content is user's markdown

### Conventions

- **Tags**: Always kebab-case slugs (e.g., `depth-first-search`), with corresponding `tagNames` in Title Case
- **Difficulties**: Exactly `Easy`, `Medium`, or `Hard` (capitalized)
- **Frontend IDs**: String, may be null
- **Timestamps**: Unix seconds in `metadata.json`, ISO 8601 in `data/*.json` and `notes.json`
- **Sorting**: `data/archive.json` sorted by `solvedAt` descending (newest first), then `frontendId` ascending for ties
- **Languages**: Currently `python3` for all, but support planned for others – check `language` field

### Website Integration

The website expects:
- `problems.json` at raw GitHub URL for listing
- `tags.json` for filter chips (shows top 20, expand to all)
- `notes.md` and `solution.py` via raw GitHub for detail view
- Extension at `ryan-westfall.info` sets `window.__leetSyncExtension = true` in MAIN world for edit gating

### Scripts

- `scripts/generate_archive.mjs`:
  - Reads all `leetcode/*/metadata.json`
  - Deduplicates by slug (keeps most recent `timestamp`)
  - Outputs `data/archive.json`, `data/problems.json`, `data/tags.json`, `data/stats.json`
  - Run with: `node scripts/generate_archive.mjs`
